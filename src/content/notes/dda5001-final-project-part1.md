看过 Transformer 的结构，不代表能立刻把它和一次训练过程对上。这次 Part I 从莎士比亚文本出发，训练字符级 GPT，比较 SGDM、AdamW 和 Muon。复习时我最想弄清楚的是：输入和标签到底长什么样？熟悉的三角形 mask 加在哪里？为什么训练 loss 很低，验证 loss 却越来越高？

## 速查

| 问题 | 先记住什么 |
| --- | --- |
| 训练目标 | 给定前面的字符，预测下一个字符。 |
| 输入与标签 | 从同一段序列取两个等长窗口，标签位置向后错一格。 |
| Causal mask | 作用于注意力分数，允许当前位置关注自身和过去，挡住未来。 |
| 参数更新 | `backward()` 计算梯度，`step()` 用优化器更新参数。 |
| 结果比较 | 本次按相同训练预算的最后 checkpoint 比较，同时看验证曲线何时回升。 |

## 从文本到一次训练

数据集使用 65 个字符的词表。字符先转换为 token ID；窗口可以从文本中间开始，不一定恰好是一个完整单词的开头。对于原始片段 `hello`，长度为 4 的输入和标签可以写成：

```text
原始序列： h  e  l  l  o
输入 x：   h  e  l  l
标签 y：   e  l  l  o
```

输入中的每个位置都有一个要预测的下一字符。输入与标签长度相同，但构造这组窗口需要原始序列中连续的 5 个字符。标签错位是**索引位置加一**，不是把 token ID 的数字加一。

本次 batch size 为 72、上下文长度为 256，所以 `x` 和 `y` 的形状都是 `[72, 256]`。程序随机取 72 个起点，各构造一对窗口。模型在一个 batch 中并行计算这些序列和各个位置；标签用于计算 loss，不参与生成 Q、K、V。

每次更新处理 $72\times256=18,432$ 个预测位置，5,000 次更新共处理 92,160,000 个预测 token。这不是 9,216 万个不同的字符：训练集约有 100 万字符，随机窗口会反复采样，也可能重叠。

模型从随机权重开始，使用 24 层、16 个注意力头和 1024 的隐藏维度，约 3.02 亿参数。`gpt2-medium` 在这里是模型配置名称，不表示加载了预训练权重。每个位置最终输出 65 个字符的 logits；交叉熵根据对应的真实下一字符计算误差。

## Mask 挡在哪里？

之前看到三角形矩阵时，我不确定它是数据还是输入。这里的 causal mask **不是数据集内容**，而是 self-attention 内部使用的规则。以输入 `hell` 为例，行表示当前预测位置，列表示可关注的输入位置：

```text
               被关注的位置
                h  e  l  l
当前位置 h      ✓  ×  ×  ×    预测 e
当前位置 e      ✓  ✓  ×  ×    预测 l
当前位置 l      ✓  ✓  ✓  ×    预测 l
当前位置 l      ✓  ✓  ✓  ✓    预测 o
```

在第二个位置，完整输入里虽然有第三个字符 `l`，但该位置只能关注 `h` 和 `e`。整个序列仍然一次输入；mask 约束的是位置之间的注意力连接，不是把输入切成四次送进去。

课程代码构造的布尔矩阵以 `True` 表示允许关注：

```python
torch.ones(size, size, dtype=torch.bool, device=device).tril(diagonal=0)
```

允许区域是**包含对角线的下三角**；需要遮挡的是不含对角线的上三角。对角线要保留，当前位置才能看到自身。代码按最大上下文长度创建 mask，使用时截取 `[:T, :T]`，并广播到 batch 和注意力头。

手写 attention 路径先对布尔 mask 取反，再把被遮挡的分数设为负无穷，随后做 softmax。另一条路径把布尔 mask 传给 PyTorch 的 scaled dot-product attention。不同 API 的布尔约定可能不同，要核对 `True` 究竟代表允许还是遮挡。

我原先觉得用 0/1 乘法或负无穷加法总能得到相同结果，但时机很重要：**softmax 前直接把未来位置的分数乘 0 并不能遮住它**，因为 $e^0=1$。若在 softmax 后将权重乘 0，通常还需对剩余权重重新归一化。

## 参数如何更新

从 logits 和标签得到 loss 后，训练循环的主要步骤是：

```text
清除旧梯度 → 前向计算和 loss → backward → 梯度裁剪 → optimizer.step()
```

`loss.backward()` 计算参数梯度；`optimizer.step()` 根据梯度和优化器状态更新参数。PyTorch 默认会累积梯度，所以需要在适当位置清除旧梯度。代码支持梯度累积，但本次配置中累积步数为 1。课程要求在累积和裁剪之后，每个优化器调用一次 `step()`。

不需要自己实现优化器内部算法，而是给 PyTorch 原生调用传入参数组、学习率和各算法设置：

- **SGDM**：`torch.optim.SGD` 加 momentum；本次 momentum 为 0.9。
- **AdamW**：使用一阶和二阶矩估计；本次 betas 为 `(0.9, 0.99)`。
- **Muon**：更新 Transformer 隐藏层的二维参数；辅助 AdamW 更新其余参数。两者管理的参数不重叠，每次更新分别执行一次。

Muon 的 `adjust_lr_fn='original'` 使用原始实现的矩阵形状相关学习率尺度调整规则；它与随训练步数变化的 warmup 和余弦衰减不是同一件事。实验中更改 Muon 的峰值学习率时，辅助 AdamW 的峰值学习率仍为 0.0003。本次 weight decay 设置为 0。

## 六组实验：为什么训练越好，验证却变差？

每种优化器分别使用默认峰值学习率和一个减半的值，其余课程规定设置保持一致。以下是最终 5,000 步的验证 loss 和墙钟时间；不是挑选验证 loss 最低的历史 checkpoint。

| 优化器 | 峰值学习率 | 最终验证 loss | 墙钟时间（分钟） |
| --- | ---: | ---: | ---: |
| AdamW | 0.0003 | 4.0327 | 27.46 |
| AdamW | 0.00015 | 3.8108 | 26.11 |
| Muon | 0.01 | 4.1210 | 31.75 |
| Muon | 0.005 | 4.1479 | 31.69 |
| SGDM | 0.1 | 1.6573 | 25.85 |
| SGDM | 0.05 | 1.5490 | 26.06 |

AdamW 和 Muon 的训练 loss 下降很快，最终接近 0；但验证 loss 先下降，随后明显上升。这与过拟合一致：模型继续拟合训练数据，却没有继续改善未参与参数更新的验证数据。AdamW 减半学习率使终点验证 loss 从 4.0327 降到 3.8108，但没有消除后期回升；Muon 减半后终点略高。SGDM 的训练 loss 下降较慢，终点验证 loss 较低。

我一开始怀疑 AdamW 的二阶矩直接导致过拟合，尤其 Muon 组也包含辅助 AdamW。但这些运行同时改变了整个优化方法，不能把差异单独归因于二阶矩。一个合理的解释是：AdamW 和 Muon 在本次设置下更快拟合训练集，也更早进入验证表现恶化的阶段；这仍是根据曲线提出的解释，需要进一步实验才能判断原因。

SGDM 也不是完全没有回升：默认学习率的最低记录验证 loss 为 1.5124（第 2,500 步），最终为 1.6573。更长训练**可能**让其继续回升，但现有记录不能说明之后会发生什么。若延长训练，还要明确是否同步改变学习率衰减计划，不能把所有变化简单归因于训练步数。

这些是单随机种子、特定数据和训练预算下的结果，不足以证明优化器的一般排名。这里比较的是最后预算处的 `last.pt`；`best.pt` 可能来自更早的验证最低点。两个概念各有用途，不能把历史最优误当作最终训练结果。
